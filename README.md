# Vajrapu Jobs

The private hub for the remote-job sprint (target: a remote FDE / AI Architect role). Built with [Astro](https://astro.build), content in Markdown, deployed as a Cloudflare Worker — the same architecture as the RAMS and Ops sites, independent of both.

| URL | What | Source |
|---|---|---|
| `/` | Today: day counter, KPI strip, **the day frame across all projects**, today's blocks with synced checkboxes | `src/pages/index.astro` |
| `/tasks/` | The 14-day sprint, day by day; expandable steps per task; ticks sync across devices (D1) | `src/pages/tasks.astro` + `src/tasks.config.ts` |
| `/notes/` | The vault: standard CV, positioning, playbooks, learning plan, STAR stories, the day frame | `src/content/notes/**` |
| `/crm/` | Applications tracker (the RAMS CRM, re-labelled): statuses Applied→Interviewing→Offer, follow-ups, copy-ready notes | `src/crm.html` + `src/api/*` |

**How the pieces hold together:** tasks are *defined* in `src/tasks.config.ts` (git), but *ticked* in D1 via `/api/ticks` — version-controlled plan, check-state that follows you between phone and laptop. Notes are plain markdown. The daily shortlist arrives from the Claude scheduled task ("Daily remote FDE job sourcing", ~9:04 IST); Block A applies to its top 5, this site logs everything.

## 1. Put it on GitHub

1. The repository: `vajrapushankar-qrush/vajrapu-jobs` (private).
2. This folder is already a git repo; it points at that remote:

```bash
git remote add origin https://github.com/vajrapushankar-qrush/vajrapu-jobs.git
git push -u origin main
```

**Required before the first Cloudflare build:** this project ships without `package-lock.json` (assembled offline). Cloudflare's builder needs one, generated by npm 10:

```bash
npx npm@10.9.2 install
git add package-lock.json && git commit -m "lockfile" && git push
```

## 2. Deploy on Cloudflare (Worker)

Workers & Pages → Create → connect the repo:

- Connect `vajrapu-jobs` · build command `npm run build`, deploy command `npx wrangler deploy`, root `/`.
- `wrangler.jsonc` holds the rest: static assets from `dist/`, `/api/*` runs `src/worker.js`.
- Every push to `main` rebuilds and redeploys; a failed build leaves the previous version live.
- Custom domain: the Worker's *Domains* tab (`fde.vajrapu.com`).

## 3. Protect it, and switch on the database

Same 10-minute sequence as the RAMS and Ops sites; the API refuses everything until it's done.

**1. Login — the Worker's Access tab.** Workers & Pages → `vajrapu-jobs` → **Access** → Manage access: scope *All traffic*; reuse your existing `Team` policy; session 730h. Save. The tab shows the **AUD tag** (team domain is already `curly-wind-4b8f.cloudflareaccess.com`).

**2. Login method.** Zero Trust → Access → Applications → the vajrapu-jobs one → Login methods → One-time PIN, instant auth on.

**3. Tell the API.** In `wrangler.jsonc` under `vars`, fill `ACCESS_AUD` (this app's AUD, not RAMS's or Ops'). Commit; the deploy applies it.

**4. Data — D1.** Storage & databases → D1 → Create → name `jobs-db`. Paste its Database ID into the `d1_databases` block and **uncomment it**. Commit. Tables are created on first use.

*(Optional)* R2 bucket `jobs-files` for screenshots → uncomment its block.

Open `/` → PIN page → Today. Install the PWA on the phone: the teal **J**, third hub on the home screen.

## 4. Living with it

- **Tick tasks** anywhere; state is per-account in D1.
- **Edit the plan**: `src/tasks.config.ts`. IDs are stable — renaming keeps the tick; never reuse an old ID. Day numbers count from `startDate` in `src/site.config.ts`.
- **The day frame** (which hours belong to which project) lives in `FRAME` in `src/site.config.ts` + `src/content/notes/plan/day-frame.md`. Re-cut it on 15 Nov and at the Day-14 retro.
- **Message wording**: `public/messages.js` (fill `linkedin` in CONFIG once). Segments: `TRADES` in `src/api/_lib.js` — the column keeps the old `trade` name so the API and CSV round-trip stay compatible.
- **Field meanings** on this site: `town` = role title, `region` = source, `contact_form_url` = posting URL, `value_gbp` = offer CTC (₹ lakh), names = the recruiter.

## 5. Running it locally (optional)

Needs Node 20.3+ (22 recommended).

```bash
npm install
npm run dev          # http://localhost:4321  (ticks/Applications need wrangler below)
npm run build        # static site -> dist/
npx wrangler dev --var DEV_USER:you@example.com   # full stack incl. API, after a build
npm test             # API + ticks tests over an in-memory D1 (Node 22.13+, node:sqlite) — 92 checks
npm run test:page    # Applications page test in a real browser (needs Playwright + Chromium)
```

## 6. If the first Cloudflare build fails

Assembled without npm-registry access: the **Worker and Applications page are fully tested** (the API + ticks suites pass against the real Worker code), but the first build is the first real **Astro** compile. If it fails, the log names the file and line; the Astro-specific files are small (`src/pages/*`, `src/components/TaskDay.astro`, `src/layouts/Base.astro`, `src/content.config.ts`, `astro.config.mjs`). Pasting the error into Claude fixes it in one go.
